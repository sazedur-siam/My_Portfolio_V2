# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Overview

Personal portfolio: a single-page React 18 app built with Vite. Plain JavaScript/JSX, no TypeScript.

## Commands

- `npm install`: install deps. Use npm; `package-lock.json` is the lockfile.
- `npm run dev` (or `npm start`): dev server on http://localhost:3000
- `npm run build`: production build into `dist/`
- `npm run preview`: serve the `dist/` build locally
- `npm run lint`: ESLint (flat config in `eslint.config.js`)
- `npm run deploy`: builds, then publishes `dist/` to GitHub Pages via `gh-pages`

There is no test runner.

## Architecture

- `index.html` (repo root) is the Vite entry; it loads `src/main.jsx`, which imports `src/index.css` and mounts `App`. Roboto and Roboto Mono load from Google Fonts in `index.html`.
- `src/App.jsx` lays out one centred `max-w-4xl` column, with the overall shell modelled on the Portfolik Framer template and the résumé block on Danie:
  - The `Navbar` top bar holds a live clock in `Bio.timezone` with the city, the anchor links, and the GitHub/LinkedIn icons.
  - Then the `Hero` panel.
  - Then the résumé block: About, Skills, Experience, Training, Education, each a `ResumeRow`. Training reuses the `Experience` component with `id`/`label`/`items` props.
  - Then the `Projects` and `Contact` panels, then a minimal `Footer`.
  - App owns the `openModal` state (`{ state, project }`) for the `ProjectDetails` dialog.
- Each fact appears in one place only:
  - GitHub/LinkedIn: the top bar.
  - CV: the hero button.
  - Availability: the hero pill.
  - Stats: About.
  - Contact: the form.

  Don't add repeat links or blurbs elsewhere.
- `src/data/constants.js` holds all site content (`Bio`, `skills`, `experiences`, `training`, `education`, `projects`, `navLinks`). Content changes go here, not in components. Keep it in line with the CV.
  - `Bio` also drives the hero and About: `title`, `tagline` (hero statement as `[dark part, muted part]`), `intro`, `availability`, `timezone`, `stats`. `email` is optional; when set, Contact mentions it.
  - `skills[].skills[]` items take a `name`, an `icon` (a `react-icons` component), and optionally the tool's brand `color` (plus `iconBg` for logos with cut-out letters, like JavaScript). Skills renders every group as mono chips, plus one row of brand-coloured logos picked by name from its `featured` list.
  - An `experiences` entry with `roles` (each with `projects` → `stack`, `points`) renders the detailed layout in `ExperienceCard`; entries with `desc`/`skills` (like `training`) render the simple card. A point that starts with a short `Label: ` renders the label in bold.
  - `projects` render as numbered cards (`01`, `02`, ...) in a 2-column grid; with an odd count the first card spans both columns. `category` is `web app` / `extension` / `android app`. Clicking a card opens the `ProjectDetails` dialog, which holds the Live/Code links. `webapp` is optional, and there are no images.
- `src/components/<Section>/index.jsx` holds one folder per section. Reusable cards live in `src/components/Cards/`. Shared layout pieces:
  - `Section.jsx`: a rounded `bg-sidebar` panel with a left-aligned `title`/`description`, used for Projects and Contact.
  - `ResumeRow.jsx`: a mono label pill, a connector line with a dot, and a panel. Rows must be adjacent siblings so the line is continuous.
  - `Chip.jsx`: a mono uppercase bordered tag.
  - `Reveal.jsx`: fade-up on scroll; takes `as` and passes other props through.
  - `Tint.jsx`: a tinted chip.
- `src/components/ui/` holds shadcn/ui primitives (Radix, generated by the shadcn CLI, configured in `components.json`). `src/lib/utils.js` exports `cn`; `src/lib/accents.js` exports the `ACCENTS` colour rotation.
- Navigation is plain in-page anchors (`#about`, `#projects`, ...); there is no router.

## Conventions

- Style with **Tailwind CSS 4** utility classes. Design tokens (colours, radius scale, `shadow-soft`, fonts) live in `src/index.css` (`:root` + `@theme inline`). Light mode only; there is no dark theme.
- The look is minimal white with light-blue Material accents:
  - Surfaces: a white page with `bg-sidebar` (`#F7FBFF`) `rounded-2xl` panels and white inner cards.
  - Colour: Blue Grey text, primary `#1E88E5`.
  - Borders: 1px borders rather than shadows.
  - Type: `font-medium` headings (avoid heavy bold), and Roboto Mono uppercase for labels, dates, chips and stats.
- Use token classes (`bg-primary`, `text-muted-foreground`, `border-border`, `bg-sidebar`) instead of hex values in components. For coloured badges use the `.tint` utility (or `<Tint>`) with a colour from `ACCENTS`; never solid saturated fills or unrelated hues. The exception is the tech logos in Skills, which use their own brand colours.
- UI icons come from `lucide-react`; brand/tech logos from `react-icons`.
- Animations use `framer-motion` (keep them subtle) and `tw-animate-css` for the shadcn components.
- Any file containing JSX must use the `.jsx` extension (Vite won't parse JSX in `.js`). Import from `src` with the `@/` alias.
- `no-unused-vars` is turned off in `eslint.config.js`.

## Gotchas

- Env vars must be prefixed `VITE_` and are read via `import.meta.env.VITE_*` (not `process.env`). Copy `.env.example` to `.env`; `.env` is gitignored, don't print or copy its values.
- `vite.config.js` uses `base: "./"` (relative asset paths) so the build works on the GitHub Pages sub-path. This relies on the app having no client-side routes.
- `Contact` sends mail through EmailJS using the `VITE_EMAILJS_*` env vars; the form field names (`from_name`, `from_email`, `subject`, `message`) must match the EmailJS template.
- The project is on React 18, but the shadcn CLI generates React 19-style components (no `forwardRef`). Any `ui/` component that Radix passes a ref to (`asChild` children such as `Button`, and portal children such as `DialogOverlay`/`SheetOverlay`) must be wrapped in `React.forwardRef`. Re-check this after running `shadcn add`. The CLI may also import `cn` from a bogus `"cn"` package; it must come from `@/lib/utils`.
- The ESLint `react-refresh/only-export-components` warnings in `ui/button.jsx`, `ui/badge.jsx` and `ui/tabs.jsx` come from shadcn exporting variant helpers and are expected.
- Build output (`dist/`) is gitignored; don't commit it.
